# Card and Deck JSON Format

## Card Fields

| Field        | Type          | Required | Notes |
|---|---|---|---|
| `id`         | string        | Yes      | Unique slug, e.g. `"legacy-02"` |
| `name`       | string        | Yes      | Display name |
| `deckId`     | string        | Yes      | Owning deck slug, e.g. `"legacy"` |
| `type`       | string        | Yes      | One of the CARD_TYPES values (see below) |
| `keywords`   | string[]      | Yes      | Subset of `['one-shot','ongoing','equipment','limited','power']`; may be `[]` |
| `text`       | string        | Yes      | Full card text (displayed verbatim; not parsed by the server) |
| `hp`         | number\|null  | Yes      | HP value for character cards only; `null` for all other card types |
| `imageUrl`   | string\|null  | No       | `null` triggers placeholder PNG generation on next import run |
| `version`    | string\|null  | No       | Inherited from deck version if `null` |
| `template`   | string\|null  | No       | SVG template key override; `null` = type-based lookup |
| `source`     | string        | Server-set | `"official"` \| `"manual"` \| `"user"` |
| `uploadedBy` | string\|null  | Server-set | User ID for `"user"` source cards; `null` for official/manual |

### CARD_TYPES Enum Values

```js
['heroCard', 'villainCard', 'environmentCard', 'heroCharacter', 'villainCharacter']
```

Note: these are different from `deckType` values (`"hero"`, `"villain"`, `"environment"`).
Character cards (`heroCharacter`, `villainCharacter`) never appear in the play deck — they
sit in the character zone for the entire game.

### imageUrl Heterogeneity

The `imageUrl` field may contain any of the following formats:

- **Root-relative path**: `"/card-images/official/legacy-inspire.jpg"` — served from the `public/` directory
- **Absolute external URL**: `"https://cdn.example.com/cards/legacy.png"` — stored and served as-is (common for user-uploaded decks)
- **Placeholder path**: `"/card-images/placeholders/legacy-02.png"` — generated by the import script
- **null**: triggers placeholder generation on the next import or upload run

The client `<img src={imageUrl}>` handles all three transparently.

## Deck Fields

| Field               | Type           | Required | Notes |
|---|---|---|---|
| `id`                | string         | Yes      | Unique slug, e.g. `"legacy"` |
| `name`              | string         | Yes      | Display name |
| `deckType`          | string         | Yes      | `"hero"` \| `"villain"` \| `"environment"` |
| `version`           | string         | Yes      | e.g. `"1.2.0"`; no default — must be explicit |
| `characterCardId`   | string\|null   | Yes      | `null` for environment decks |
| `characterVersion`  | string\|null   | Yes      | Version of character card; `null` for environment |
| `cardCount`         | number         | Derived  | Computed by import script from matching card records; do not set manually |
| `sideDeck`          | object\|null   | No       | See side deck shape below |
| `setupInstructions` | string\|null   | No       | Displayed as a setup banner in the lobby |
| `source`            | string         | Server-set | `"official"` \| `"manual"` \| `"user"` |

### Side Deck Shape

```json
{
  "id": "aeon-girls-box",
  "name": "The Aeon Girls Box",
  "version": "1.0.0",
  "cardIds": ["aeon-girls-01", "aeon-girls-02"],
  "setupInstructions": "Remove the top 5 cards of the hero deck before shuffling."
}
```

## Running the Import Script

```bash
node server/scripts/importSotmData.js
```

For development with incomplete deck sizes (fewer than 40/25/15 cards):

```bash
node server/scripts/importSotmData.js --skip-count-validation
```

The script upserts cards and decks into MongoDB, computes `cardCount`, generates placeholder
images for any card with `imageUrl: null`, and logs a field-level diff for any card or deck
that changed version since the last run.

Official decks (source = "official") are validated **strictly** against expected sizes:
- Hero decks: 40 play cards (character card not counted)
- Villain decks: 25 play cards
- Environment decks: 15 play cards

Missing or surplus cards are listed in the error output.

## Version Bump Workflow

1. Update the `version` field in the relevant JSON files under `data/sotm/`
2. Re-run `node server/scripts/importSotmData.js`
3. The script logs a diff of changed fields for each updated card/deck
4. `gameOutcomes` documents are never modified — historical games retain their version tags
5. Auto-tags on new game outcomes will reflect the new version (`deck:{id}@{newVersion}`)
